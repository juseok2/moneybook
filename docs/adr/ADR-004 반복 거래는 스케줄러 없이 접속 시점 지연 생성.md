# ADR-004: 반복 거래는 스케줄러 없이 접속 시점 지연 생성

## 상태

승인됨 (2026-07-22)

## 상황 (Context)

고정 수입,고정 지출 구현을 위해 스케줄러를 돌릴것인지 접속시점에 지연 생성할 것인지 선택이 필요한 상황
서버리스 방식 사용을 계획중

## 결정 (Decision)

반복거래 데이터는 접속시점에 지연생성 하기로 결정함

## 근거 (Rationale)

가계부는 실시간으로 데이터를 필요로 하는것이 아니기 때문에 접속 시점에 사용자의 데이터를 생성해도 된다 그래서 지연생성 방식을 채택
앞서 서버리스 방식을 사용하기로 했다 스케줄러를 돌리기 위해선 24시간 돌아가는 서버 필요. 그래서 스케줄러 방식 사용은 복잡하고 즉시성이 불필요한 앱에서 해당 비용을 지불할 이유가 없음

## 대안과 기각 사유 (Alternatives)

대안 스케줄러 방식
기각사유 데이터가 항상 최신 데이터이다 하지만 24시간 돌아가는 서버가 필요하며 사용자는 접속할 때 내 데이터가 정상이기만 하면 되기 때문에 기각

## 결과 (Consequences)

동시 접속 할 경우의 문제가 발생할 수 있기 때문에 반복 규칙 ID+날짜 방식으로 코드를 생성하고 유니크 제약으로 중복 생성 방지 필요
